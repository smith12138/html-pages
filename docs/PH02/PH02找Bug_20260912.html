#级别模块标题现象 / 复现
B01 P2 出款规则 可提现时段 start>end 无逻辑校验 PUT /admin/withdraw-rules/update 设 daily_allow_start_minute=1200、daily_allow_end_minute=600 → code=0 接受。对照：start==end(600,600) 被拒 11969、单值越界(>1440) 返 400、min>max/daily_max
B02 P2 配置管理 现有配置原样回存报 400（更新校验严于存量数据） 把列表接口 GET 到的一条现有记录，原封不动 PUT 回更新接口即 400：① vip-configs 存 icon_url=""(全10级)，update 校验 IconUrl≥1；② vip-withdraw-no-review-rules 存 vip_level=-1，update 校验 VipLevel≥0；③ banners 存 banner_name 含空格/下划线(如 "QA Banner")，update 正则 ^[\p{L}\p{N}]+$ 拒。影响：运营编辑上述记录的其它字段（如 VIP 返水率/门槛）并保存时被无关字段校验拦死；且 VIP 空 icon_url 一旦被改就再也无法置回空。
B03 P2 错误处理 部分业务/鉴权失败返 HTTP 500 + 双重字符串化 JSON 期望业务失败返 HTTP 200+base.code、鉴权失败返 401/403；实际部分场景返 HTTP 500 且 message 是被字符串化的内层 JSON，前端无法解析。实例：资金密码连错锁定 → 500 reason=BFFService message="{\"base\":{\"code\":10332}}"；用户 token 调 /admin/* → 500 reason=AdminService code=4002(鉴权拒绝，应 401/403)。
B04 P2 错误处理 业务失败 message 仅为服务名，无可读文案 几乎所有业务失败(非 400 校验类)的 base.message 都是 "ADMIN" 或 "BFF"(服务名)，无人类可读原因。实例：加扣款失败 11980 message="ADMIN"；出款 10320/10300 message="BFF"；规则冲突 11989 message="ADMIN"。影响：前端须自行维护全部数字码→文案映射；后台运营看到 "ADMIN" 无法判断失败原因。
B05 P3 金额精度 存款/规则金额接受亚分精度 POST /bff/wallet/deposit amount=100000001(₱100.000001) → code=0，DB hash_deposit_orders 落库 amount=100000001 status=1；PUT /admin/withdraw-rules/update min_amount=100000001 → code=0。金额最小粒度应为分(10000 微单位)，系统未做整除校验，可产生 ₱100.000001 这类亚分金额，累积舍入/对账风险。
B06 P3 资金密码 资金密码接受弱 PIN POST /bff/wallet/withdraw-password/set 仅校验长度 6-12；111111 / 000000 / 123456 / abcdef 均设置成功 code=0，无连号/重复/字典校验。
B07 P3 校验规则 展示字段正则过严（禁空格/下划线） banner_name、加扣款 remark 等正则 ^[\p{L}\p{N}]+$ 仅允字母数字；正常展示名 "QA Banner"(含空格) create/update 均 400；备注无法写含空格/标点内容。建议展示/备注类字段放宽。
B08 P3 分页 列表分页参数无校验 GET /admin/withdraw-orders 等：page.page=-1、page.page_size=0 / -5 / "abc" 均 HTTP200 返默认10条不报 400；page_size 无上限。建议对分页入参做范围校验。
