一、聊天插件对接流程（包网需要）

让包网站点右下角出现 SaleSmartly 聊天气泡，用户点击即可进线

1.1 后台准备（SaleSmartly 控制台）

  1. 创建聊天插件：后台「集成 → 聊天插件 → + 添加」，新建插件。列表中可见每个插件的：开启状态、品牌信息、语言、分配成员、自动化（机器人流程数）、站点、备注。
  2. 基础信息（编辑插件 →「聊天插件」Tab）：品牌名称、语言（可"自动匹配"或指定）、欢迎语等。
  3. 入口配置（编辑插件 →「入口配置」Tab）：入口布局（窗口内展示 / 竖排展开）、入口位置（靠左 / 靠右）、入口样式（系统默认 / 自定义）、移动端与 PC 端图标大小及底部间距。
  4. 渠道集成入口管理（入口配置底部「渠道集成入口 → 管理」）：可在聊天窗口内聚合多个渠道入口（TikTok App、Email、Messenger、聊天插件等），逐个选择集成方式并开关"显示输入框"。
  5. 获取嵌入代码：后台生成形如 project_<项目ID>_<插件ID>_<时间戳>.js 的脚本地址。

插件配置（后台界面）

1.2 站点接入（前端嵌入）

标准接入方式，将脚本放在 </body> 前或 <head> 内，推荐 defer 异步加载：

html<!-- 放在 </body> 前或 <head> 内，推荐 defer 异步加载 --> <script src="https://plugin-code.salesmartly.com/js/project_725936_767293_1781079042.js" defer></script>
  • 脚本域名：plugin-code.salesmartly.com　协议：HTTPS　加载方式：defer（不阻塞渲染）
  • 测试页配置示例：Project ID 725936、Plugin ID 766848
包网注意：包网是"一套代码、多个站点 / 品牌"。建议每个品牌 / 站点对应一个独立插件（独立 project / plugin id），通过后台「站点」绑定域名，前端按当前域名动态下发对应的插件 JS 地址。

1.3 入口关闭（按需隐藏渠道入口）

若聊天窗口内某个渠道入口（如某个 TikTok / Email 入口）暂时不想展示，可在「渠道集成入口管理」里把对应入口直接关闭，无需改代码。

二、聊天插件数据传递流程（包网需要）

用户进线时，把"我方系统里的玩家身份/资料"通过 JSSDK 传给 SaleSmartly —— 对应官方文档 2.2.1 设置登录信息　·　官方 JSSDK 文档 ↗

2.1 JSSDK 全局对象

引入插件 JS 后，页面会注入全局变量 ssq，所有 API 通过 ssq.push('方法名', 参数/回调) 调用。

2.2 设置登录信息（2.2.1，最关键）

在用户登录包网账号后调用，把玩家身份写入 SaleSmartly 客户档案：

javascriptssq.push('setLoginInfo', { user_id: 'b58e64cfxs2ym', // ★必填：玩家唯一标识（加密ID），最长 300 字符 user_name: 'test_yy', // ★必填：展示名（可用玩家昵称/账号） language: 'ru-RU', // 插件语言 phone: '861592014xxxx', // 完整手机号（含国家区号） email: 'test@test', // 邮箱 description: 'comboB\nClient', // 备注（可换行） label_names: ['Label1', 'Label2'], // 标签数组（如 VIP等级/代理线） update_label_type: 'update', // 标签更新方式：'append' 追加 / 'update' 覆盖 custom_fields_ext: { "1210": "test11", "more": ["s1", "s2"] } // 自定义字段 });
字段必填说明 / 包网用途
user_id是玩家唯一ID（加密），SaleSmartly 据此识别同一玩家；建议用包网玩家ID或其哈希，≤300字符
user_name是展示名
phone否含国家区号
email否邮箱
language否插件语言（如 ru-RU / en-US / zh-CN）
description否备注，支持 \n 换行
label_names否标签数组，可打 VIP等级、币种、代理线、风控标记等
update_label_type否append=追加；update=覆盖
custom_fields_ext否自定义字段，key 为后台字段ID。包网可在此带上玩家ID、币种、余额、代理ID、最近订单号等，供客服侧直接可见

2.3 清理登录信息（2.2.2）

玩家退出登录（或 PWA 站点切换账号）后清理身份，避免串号：

javascriptssq.push('clearUser'); // 退出登录后执行

2.4 窗口控制

javascriptssq.push('chatOpen'); // 2.3 打开聊天窗口 ssq.push('chatClose'); // 2.4 关闭聊天窗口

2.5 隐藏图标 + 自定义按钮（2.6）

包网常需用自己的"客服"按钮替换默认气泡，用 hideIcon 隐藏默认图标，再绑自定义按钮事件：

html<script src="https://assets.salesmartly.com/js/project_23232_xxxxx_xxxxxxxxxx.js"></script> <script> // 隐藏默认图标（true=隐藏，false=不隐藏） window.__ssc.setting = { hideIcon: true }; // 自定义按钮事件：点我方按钮 → 打开聊天窗 function openChat() { ssq.push('chatOpen'); } </script>

2.7 数据传递时序（推荐）

玩家登录包网 → 前端拿到玩家档案 → ssq.push('setLoginInfo', { user_id, user_name, custom_fields_ext:{玩家ID,币种,订单号...} }) → 玩家点客服按钮 → ssq.push('chatOpen') → 玩家发消息 / 点菜单 → SaleSmartly 平台收到 → 触发机器人 + Webhook 推送到 GO 后端（见第五节） 玩家退出 → ssq.push('clearUser')

四、前端：SaleSmartly 怎么发送菜单

充值 / 提现 / 账号 / 其他 / 人工客服 —— 菜单不是前端"硬发"，而是在后台用机器人/自动化流程配置
结论：菜单应在 SaleSmartly 后台用「机器人 / 自动化流程」配置快捷菜单 / 按钮（即插件列表里"自动化"那一列）。前端的职责是"进线 + 传身份 + 触发流程"。

4.1 推荐方案 A：后台机器人配置快捷菜单（首选）

  1. 后台进入该插件的「自动化 / 机器人」流程编辑器。
  2. 配置进线欢迎消息 + 快捷回复按钮（菜单）：充值提现账号其他人工客服
  3. 为每个按钮绑定动作：
    • 业务类（充值/提现/账号/其他）：回复对应话术并收集订单号（引导输入或调信息收集表单），随后流程把"按钮ID + 订单号"带出 → Webhook 推给后端查单。
    • 人工客服：转人工 / 分配坐席。
  4. 用户点击按钮 → 平台产生一条 button 类型消息（含 payload.button_reply.id / title，见第五节），Webhook 推送给 GO 后端识别选择。
优点：菜单可视化维护、可多语言、改话术不发版；与 Webhook 的 button 消息天然对应，后端识别简单。

4.2 方案 B：前端自建菜单 UI + JSSDK 代发

若产品要在站点页面上自绘菜单按钮（非聊天窗口内），可用 JSSDK：

javascript// 点击"充值"菜单 document.querySelector('#menu-recharge').onclick = function(){ ssq.push('chatOpen'); // 打开聊天窗 ssq.push('sendTextMessage', '充值'); // 代用户发文本，触发后台关键词流程 };
  • 后台按关键词（"充值/提现/账号/人工客服"）配置自动化触发。
  • 局限：sendTextMessage 只发纯文本，不带结构化 payload，后端只能按文本匹配。

4.3 方案 C：主动发送接口下发"按钮模板"消息（后端下发）

由后端通过 SaleSmartly 主动发送消息接口下发带按钮的模板消息（msg_type:3 + buttons）。

渠道限制：官方文档明确"文本按钮消息 / 图片+文本按钮消息" 聊天插件(Plugin)、WhatsApp APP、Telegram APP、Instagram 渠道不支持。因此对"聊天插件"渠道，菜单按钮优先用方案 A（后台机器人快捷菜单）；后端主动回复时用纯文本 / 轮播文本模板（Plugin 支持 template.text），不要依赖按钮模板。

4.4 前端落地建议（包网）

  • 进线即 setLoginInfo 带齐玩家ID / 订单上下文 → chatOpen。
  • 菜单本体放后台机器人（方案 A）。
  • 站点内若要露出"充值/提现/账号/人工客服"快捷入口，用方案 B 触发对应流程。
  • 五个菜单对应后端 query_type：充值=recharge、提现=withdraw、账号=account、其他=other、人工客服=transfer_human。

五、GO 后端：如何解析 SaleSmartly 的数据传递事件

依据 SaleSmartly Webhook API 接口文档。GO 后端作为 Webhook 接收端 + 主动发送端　·　Webhook API 文档 ↗

5.1 Webhook 配置与验签

POST http(s)://host?timestamp=TIMESTAMP&signature=SIGNATURE
  • Header：content-type: application/json
  • 配置参数：url（回调地址）、secret（验签密钥）
  • 签名算法：把请求参数名按字典序排序，拼到 secret 之后做 MD5。
    • 消息示例：md5(secret&data=123&event=message)
    • 事件示例：md5(secret&data=123&event=add_user)
  • GO 端先校验 signature，确认请求来自 SaleSmartly 官方再处理。

5.2 三大类回调

类别event 取值说明
接收消息message用户发来的 text / button / image / file / system / email 消息
接收事件add_user / update_user / device_event新增客户 / 客户信息更新 / 设备状态变更
主动发送—（你方调用对方接口）向用户回写消息

5.3 接收消息（event = message）公共字段

字段说明
msg_type消息类型：text / button / image / file / system_message / email
chat_user_id用户ID（关键，关联玩家身份）
sequence_id消息ID
msg消息内容（String 或 Object）
chat_session_id / chat_session_encrypt_id会话ID / 会话加密ID
channel渠道编码（聊天插件=2）
sender_type发送方：1=用户，2=项目成员
sys_user_id接待客服ID（0=未分配，-1=机器人）
channel_name社媒名称

按钮点击（菜单识别的核心）msg_type: "button"

json{ "event": "message", "data": { "chat_user_id": "65094291e106072b7e40ff21", "msg_type": "button", "msg": "充值", "payload": { "type": "button_reply", "button_reply": { "id": "ACT:24545", "title": "充值" } }, "chat_session_id": 130925, "channel": 2, "sender_type": 1, "sys_user_id": 0 } }

→ GO 端据 payload.button_reply.id/title 判断用户点了哪个菜单（充值/提现/账号/其他/人工客服）。文本消息 msg_type:"text" 的 msg 为文本，用户输入的订单号通常走这里。

5.4 GO 解析示例（结构体 + Handler 骨架）

gotype WebhookEnvelope struct { Event string `json:"event"` Data json.RawMessage `json:"data"` } type MessageData struct { MsgType string `json:"msg_type"` ChatUserID string `json:"chat_user_id"` Msg json.RawMessage `json:"msg"` // text 为字符串，email/system 为对象 Payload *ButtonPayload `json:"payload"` // button 才有 ChatSessionID json.Number `json:"chat_session_id"` Channel int `json:"channel"` SenderType string `json:"sender_type"` SysUserID int `json:"sys_user_id"` } type ButtonPayload struct { Type string `json:"type"` ButtonReply struct { ID string `json:"id"` Title string `json:"title"` } `json:"button_reply"` } func handleWebhook(w http.ResponseWriter, r *http.Request) { // 1) 验签：md5(secret & 按字典序排序的参数...) == signature if !verifySign(r) { http.Error(w, "bad sign", 403); return } var env WebhookEnvelope _ = json.NewDecoder(r.Body).Decode(&env) switch env.Event { case "message": var m MessageData _ = json.Unmarshal(env.Data, &m) if m.SenderType != "1" { break } // 只处理用户发来的 switch m.MsgType { case "button": menu := m.Payload.ButtonReply.Title // 充值/提现/账号/其他/人工客服 // 投递 MQ：{player_id: m.ChatUserID, menu, session: m.ChatSessionID} case "text": var text string; _ = json.Unmarshal(m.Msg, &text) // 识别订单号正则 → 投递 MQ } case "add_user", "update_user": // 解析 UserEvent（见 5.5），补全/更新玩家档案映射 case "device_event": // 设备状态变更（一般忽略） } w.Write([]byte(`{"code":0,"msg":"Success"}`)) // 按文档返回成功 }

5.5 接收事件（add_user / update_user）

进线建档 / 更新时推送，可用来落库玩家与 SaleSmartly 客户的映射：

字段说明
chat_user_id用户ID
name / remark_name名称 / 备注名
phone / email联系方式
labels标签数组 [{"id":36577,"label_name":"3"}]
custom_field自定义字段 JSON（update 仅返回变更字段）
ad_referral广告来源 {"ad_id":123,"ad_title":"title"}
sys_user_id接待成员（0=未分配，-1=机器人）
created_time / updated_time创建 / 更新时间（Unix）
关键锚点：前端 setLoginInfo.user_id 与 Webhook 的 chat_user_id 是同一玩家。GO 端据此把 SaleSmartly 会话与包网玩家ID绑定。

5.6 主动发送（回写用户）

POST https://webhook.salesmartly.com/plugin/send

鉴权 POST host?timestamp=TIMESTAMP&signature=webhook_token，Header content-type: application/json。通用 data 字段：msg_type（默认 3，轮播为 27）、msg（template 结构）、chat_user_id、chat_session_id、send_time、channel。

json{ "data": { "msg_type": 3, "msg": { "template1": { "text": "您的提现订单 R20260616 正在出款中，预计10分钟到账。" } }, "chat_user_id": "6537425481afde78d31e7651", "chat_session_id": "130925", "send_time": "1695799154645", "channel": 2 } }

六、Python 后端：TT 平台独立工作流

用户进线即通过 MQ 拿到玩家ID及其他信息，再用"用户咨询的问题 / 订单号"去包网 API 查数据，返回给用户（TT = TikTok 渠道，独立成一条工作流）

6.1 工作流总览

SaleSmartly(TT进线/消息/按钮) → GO Webhook 解析 → 投递 MQ（topic: tt_inbound） payload: { player_id(chat_user_id), channel, session_id, msg_type, menu/text, order_no? } → Python 消费者（TT 独立 worker） 1) 拿 player_id 等上下文 2) 解析咨询意图：菜单(充值/提现/账号/其他) + 订单号 3) 调用【包网 API】查询对应数据（见第三节字段） 4) 组织回复文案（可走 AI 润色） → 回写：调用主动发送接口 / 经 GO /plugin(对应渠道)/send 返回给用户

6.2 MQ 消息约定（GO → Python）

json{ "trace_id": "uuid", "platform": "TT", "channel": 16, "player_id": "65094291e106072b7e40ff21", // = SaleSmartly chat_user_id "chat_session_id": "130925", "msg_type": "button", // button | text "menu": "充值", // button 时有：充值/提现/账号/其他/人工客服 "text": "R20260616xxxx", // text 时有：原文（含可能的订单号） "order_no": "R20260616xxxx", // GO 端正则预抽取（可选） "send_time": "1695799154645" }

6.3 Python 消费者骨架

python# tt_worker.py —— TT 平台独立工作流 import re, json MENU_TO_QUERY = { "充值": "recharge", "提现": "withdraw", "账号": "account", "其他": "other", "人工客服": "transfer_human", } ORDER_RE = re.compile(r'\b[RWO]?\d{8,}\b') # 订单号识别（按包网规则调整） def on_message(raw: bytes): ev = json.loads(raw) if ev.get("platform") != "TT": # TT 独立工作流，只处理 TT return player_id = ev["player_id"] session = ev["chat_session_id"] # 1) 解析意图 query_type = MENU_TO_QUERY.get(ev.get("menu"), None) order_no = ev.get("order_no") or _extract_order(ev.get("text", "")) if ev.get("menu") == "人工客服": return transfer_to_human(player_id, session) # 若仅点菜单还没给订单号 → 引导用户输入 if query_type in ("recharge", "withdraw") and not order_no: return reply(player_id, session, "请提供您的订单号，我帮您查询～") # 2) 调包网 API data = baowang_query(player_id=player_id, query_type=query_type, order_no=order_no) # 3) 组织回复（可接入 AI 客服润色） reply(player_id, session, render_answer(query_type, data)) def _extract_order(text: str): m = ORDER_RE.search(text or "") return m.group(0) if m else None

6.4 调用包网 API（见第三节）

pythonimport time, hashlib, requests BAOWANG_BASE = "https://api.baowang.example/api/cs/query" APP_ID, APP_SECRET = "xxx", "yyy" def baowang_query(player_id, query_type, order_no=None, page=1, page_size=10): ts = int(time.time()) body = { "app_id": APP_ID, "timestamp": ts, "player_id": player_id, "query_type": query_type, "order_no": order_no, "page": page, "page_size": page_size, } body["sign"] = _sign(body, APP_SECRET) r = requests.post(BAOWANG_BASE, json=body, timeout=5) return r.json().get("data") def _sign(body, secret): items = "&".join(f"{k}={body[k]}" for k in sorted(body) if k != "sign" and body[k] is not None) return hashlib.md5(f"{items}&secret={secret}".encode()).hexdigest()

pythondef reply(player_id, session, text): payload = { "data": { "msg_type": 3, "msg": {"template1": {"text": text}}, "chat_user_id": player_id, "chat_session_id": session, "send_time": str(int(time.time()*1000)), "channel": 16, # TT 渠道；聊天插件则为 2，并改用 /plugin/send } } # 经 GO 统一出口或直连 SaleSmartly 主动发送接口（带 timestamp+signature 验签） send_via_salesmartly(payload)
渠道差异提醒：TikTok App(16) 不支持主动发送（见附录对照表，主动发送列为 ✗）。因此 TT 工作流的"回复用户"通常需走 SaleSmartly 机器人 / 坐席在会话内回复，或确认所用 TT 渠道类型是否开通主动发送权限；落地前务必与 SaleSmartly 确认 TT 渠道的回写方式。聊天插件(Plugin, 2) 支持主动发送（/plugin/send），包网站点内的 TT 引流用户若走插件渠道则可直接回写。

6.6 工作流要点

  • 独立部署：TT worker 与其他渠道 worker 分离（独立 topic / 消费组 / 限流），互不影响。
  • 幂等：以 sequence_id / trace_id 去重，防 Webhook 重推。
  • 超时兜底：包网 API 超时 / 失败时，回复"正在为您查询，请稍候"并转人工。
  • 上下文：菜单与订单号可能分两条消息到达，需在会话维度缓存（如 Redis，key = chat_session_id）。
  • 意图识别：菜单优先用 button payload；自由文本走关键词 / AI 意图分类。
