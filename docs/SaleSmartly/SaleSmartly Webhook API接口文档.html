一、Webhook 接收消息接口

接收用户发送的各类消息（暂不支持群消息）

1.1 概述与配置参数

需根据 SaleSmartly 的规范，对添加的 Webhook 地址实现一个 POST 请求接口。当系统接收到新消息时，会调用该 Webhook 将消息推送至配置的地址。

配置参数类型说明
urlStringWebhook 的请求地址
secretString用于 Webhook 端验证请求是否来自 SaleSmartly 官方

1.2 请求地址与签名验证

POST http(s)://host?timestamp=TIMESTAMP&signature=SIGNATURE

地址中携带的参数用于安全校验：

  • timestamp — 请求时间戳
  • signature — 签名校验值，Webhook 端可据此判断请求是否来自 SaleSmartly 官方
签名算法：将参数名称按字典序排序后，衔接到 secret 后进行 MD5 加密。
示例：md5(secret&data=123&event=message)

Header：content-type: "application/json"

Body 参数类型说明
eventString推送 Webhook 的事件名。"message" 表示新消息推送
dataObject新消息的数据体（格式见下方）

1.3 消息数据格式（data 字段）

以下为 data 中各消息类型的字段说明。所有类型共有以下公共字段：

公共字段类型说明
msg_type *String消息类型标识（见下方各类型）
chat_user_id *String用户 ID
sequence_id *Int消息 ID
send_time *String消息发送时间
msg *String/Object消息内容
chat_session_id *String会话 ID
chat_session_encrypt_id *String会话加密 ID
channel *Int社媒渠道编码（见渠道对照表）
channel_uid *String社媒渠道 ID
sender_type *String发送方：1=用户，2=项目成员
sender *String发送人（用户 ID 或项目成员 ID）
sys_user_id *Int当前接待客服 ID（0=未分配，-1=机器人）
channel_name *String当前社媒名称

类型一：text（文本消息）

字段类型说明
msg_typeString"text"
msgString文本消息内容
quote_chatString引用回复内容（可选）
支持渠道：Messenger(1)、Plugin(2)、Instagram(5)、Line(6)、WhatsApp API(7)、WhatsApp APP(12)、Telegram(15)、TikTok(16)

类型二：button（按钮点击）

字段类型说明
msg_typeString"button"
msgString按钮文本内容
payloadObject按钮信息（含 type、button_reply.id、button_reply.title）
支持渠道：Messenger(1)、Line(6)、WhatsApp API(7)

类型三：image（图片消息）

字段类型说明
msg_typeString"image"
msgString图片 URL 地址
支持渠道：Messenger(1)、Plugin(2)、Instagram(5)、Line(6)、WhatsApp API(7)、WhatsApp APP(12)、Telegram(15)、TikTok(16)

类型四：file（文件消息）

字段类型说明
msg_typeString"file"
msgString文件 URL 地址
支持渠道：Messenger(1)、Plugin(2)、Instagram(5)、WhatsApp API(7)、WhatsApp APP(12)、Telegram(15)

类型五：system_message（系统消息）

字段类型说明
msg_typeString"system_message"
msgObject系统事件内容（WhatsApp 进/退群通知等）

msg 对象字段：

字段说明
type事件名称：join_group / leave_group
name用户 WhatsApp 昵称
origin_phone用户手机号码（带国家区号）
country_code国家区号（如 +1）
phone用户号码（不带国家区号）
group_name群组名称
group_uid群组 ID
event_id事件 ID
timestamps进/退群时间
仅支持渠道：WhatsApp APP(12)

类型六：email（邮件消息）

字段类型说明
msg_typeString"email"
msgObject邮件内容（含 title、msg、attachments）

msg 对象字段：

字段说明
title邮件标题
msg邮件正文（HTML 格式）
attachments附件列表（JSON 数组）
仅支持渠道：Email(3)

二、Webhook 接收事件接口

接收客户新增、更新及设备状态变更等事件推送

2.1 事件类型概览

与消息接收接口相同的配置方式和签名验证规则，但 event 字段值不同。

签名示例：md5(secret&data=123&event=add_user)
Body 参数类型说明
eventString事件名：add_user=新增客户、update_user=客户信息更新、device_event=设备状态变更
dataObject事件数据体

2.2 数据格式

事件一：add_user（新增客户）

字段类型说明
chat_user_id *String用户 ID
name *String名称
remark_name *String备注名
phone *String手机号码
email *String邮箱
remark *String备注
channel *Int社媒渠道编码（见渠道对照表）
labels *String标签 JSON 数组：[{"id":36577,"label_name":"3"}]
custom_field *String自定义字段 JSON（仅返回更新的字段）：{"field1":36577,"field2":[36577,36566]}
ad_referral *String广告 ID 信息 JSON：{"ad_id":123,"ad_title":"title"}
sys_user_id *Int接待成员 ID
channel_name *String当前社媒名称
created_time *Int创建时间（Unix 时间戳）
updated_time *Int更新时间（Unix 时间戳）
支持渠道：Messenger(1)、聊天插件(2)、Email(3)、Telegram(4)、Instagram(5)、Line(6)、WhatsApp API(7)、Facebook主页评论(8)、Slack(10)、企业微信(11)、WhatsApp APP(12)、Instagram评论(13)、Telegram App(15)、TikTok App(16)、TikTok评论(17)、VKontakte(18)

事件二：update_user（客户信息更新）

字段结构与 add_user 完全相同，额外注意：

  • sys_user_id：0=未分配，-1=机器人
  • custom_field：仅返回进行更新的自定义字段，不返回全部
额外支持渠道（相比 add_user 新增）：Zalo(19)、TikTok商业号(20)、TikTok商业号评论(21)

事件三：device_event（设备状态变更）

目前仅支持 WhatsApp APP 渠道。手动断开连接的账号失效状态不会推送，每天下午6点的设备失效汇总通知不推送。
字段类型说明
id *Int云设备 ID
name *String设备名称
phone *String手机号码
avatar *String云设备头像
channel *Int社媒渠道：12=WhatsApp APP、15=Telegram App、16=TikTok App、19=Zalo
status *Int0=未连接、1=有效、2=失效
channel_name *String当前社媒名称
created_time *Int创建时间
updated_time *Int更新时间

2.3 请求示例

示例 1：新增客户（add_user）

JSON{ "event": "add_user", "data": { "chat_user_id": "2213217a81", "name": "测试", "remark_name": "", "phone": "", "email": "1@1.cc", "channel": 12, "remark": "", "labels": [ { "id": 36577, "label_name": "3" } ], "custom_field": { "custom_field_name1": 111, "custom_field_name2": [222, 333] }, "ad_referral": { "ad_id": 111, "ad_title": "title" }, "sys_user_id": 1, "channel_name": "testName", "created_time": 1732689659, "updated_time": 1732776394 } }

示例 2：客户信息更新（update_user）

JSON{ "event": "update_user", "data": { "chat_user_id": "2213217a81", "name": "测试", "remark_name": "", "phone": "", "email": "1@1.cc", "channel": 12, "remark": "", "labels": [ { "id": 36577, "label_name": "3" } ], "custom_field": { "custom_field_name1": 111, "custom_field_name2": [222, 333] }, "ad_referral": { "ad_id": 111, "ad_title": "title" }, "sys_user_id": 1, "channel_name": "testName", "created_time": 1732689659, "updated_time": 1732776394 } }

示例 3：设备状态变更（device_event）

三、主动发送消息接口

通过 SaleSmartly 接口主动向用户推送消息

3.1 各渠道接口地址

根据目标渠道选择对应的接口地址，统一使用 POST 请求：

渠道接口地址
WhatsApp APIhttps://webhook.salesmartly.com/whatsapp/send
Messengerhttps://webhook.salesmartly.com/messenger/send
Linehttps://webhook.salesmartly.com/line/send
WhatsApp APPhttps://webhook.salesmartly.com/individual_whatsapp/send
Instagramhttps://webhook.salesmartly.com/instagram/send
Plugin（聊天插件）https://webhook.salesmartly.com/plugin/send
Telegram APPhttps://webhook.salesmartly.com/telegram_app/send

请求参数

POST http(s)://host?timestamp=TIMESTAMP&signature=webhook_token

Header：content-type: "application/json"

配置参数类型说明
urlStringSaleSmartly 接口地址（见上表）
signatureString用于接口验证信息有效性（即 webhook_token）
dataJSON需要推送的消息数据

3.2 消息格式与示例

data 通用字段

字段类型说明
msg_type *String默认为 3（轮播消息为 27）
msg *Object消息内容（template 结构）
chat_user_id *String用户 ID
chat_session_id *String会话 ID
send_time *String消息发送时间

示例 1：回复文本消息

JSON{ "data": { "msg_type": 3, "msg": { "template1": { "text": "您选择商品是手套，链接：https://ss.com" }, "template2": { "text": "您选择商品是手套，链接：https://ss.com" } // 最多支持 5 个 template }, "chat_user_id": "6537425481afde78d31e7651", "chat_session_id": "130925", "send_time": "1695799154645", "channel": 1 } }
