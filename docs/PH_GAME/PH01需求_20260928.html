板块一

自动化营销（营销旅程编辑器）· 体验优化

目标：营销旅程编辑器目前对运营人员不友好——大量英文技术字段、靠手填 ID、报错看不懂。以下从用户体验角度提出优化，提升运营可用性。

一、一堆英文没翻译，运营看不懂 → 改中文 / 符号
1
比较运算符
现：EQ / GT / GTE / LT / LTE / IN / EXISTS
→ 改成 = ／ > ／ ≥ ／ < ／ ≤ ／ 包含 ／ 存在(有)
2
指标名
现：registered_elapsed_minutes、never_successfully_deposited
→ 改中文（注册已过分钟数、从未成功充值）
3
数据来源
现：users.created_at、deposit_orders（英文表名）
→ 运营完全看不懂，改中文或直接隐藏（属技术字段）
4
计算时点
现：RUN_START
→ 每轮运行开始时
5
入口模式
现：PER_RUN_SNAPSHOT
→ 每轮人群快照
6
并发策略
现：FORBID
→ 禁止并发
二、靠手填 ID / 编号，缺选择器 → 运营不知道该填什么
7
标签定义 ID
现：要手填数字 ID（如 1191），运营根本不知道哪个 ID 是哪个标签
→ 带入会员标签模块的标签列表做下拉选择（显示标签名，点选即可）
8
MASTER / TEAM / GROUP / CHANNEL
现：同样靠手填编号、无下拉
→ 改成从已授权列表里选
三、报错 / 约束不友好
9
标签估算失败是英文报错
现：REFERENCE_REQUIRED: tag source needs definition, serving version, and snapshot ids
→ 改中文友好提示（如"该标签尚未发布可用快照，请先发布或另选一个"）
10
标签必须有"服务版本"才能圈选，但选前无提示
现：选完点估算才报错，运营白选
→ 选标签时就只列出"可用（有服务版本）"的标签，或直接标注状态
四、可精简
·
「数据来源」「计算时点」这类技术字段运营基本用不到，建议默认隐藏 / 收进"高级设置"，让主界面更清爽。
板块二

提现限制调整 · 开发实现

核心：去掉每日提款次数限制，改为按 VIP 等级的每日累计成功提款金额上限；单笔最低 ₱100；超限按场景友好弹窗。可提额度（打码流水）这道门保持不变，与金额上限一起「取小」生效。

1 VIP 每日提款额度表（确定值）

每个 VIP 等级「每日累计成功提款金额上限」如下（数值沿用现「免审额度」）：

VIP 等级每日提款额度上限（PHP）VIP 等级每日提款额度上限（PHP）
VIP0500VIP55,000
VIP11,000VIP68,000
VIP21,500VIP712,000
VIP32,000VIP820,000
VIP43,000VIP950,000

配置项，后台可改。建议存于 VIP 等级配置（如 vip_levels.daily_withdraw_amount_limit）。

2 核心规则

① 去次数：取消每日提款「次数」限制（拆成多笔小额也无所谓，被总额度卡死）。
② 单笔最低 ₱100：单次提款金额 不得低于 100（原 50 提高到 100）。
③ 每日额度按「实际成功」计：「今日已用额度」= 当天成功出款的累计金额；被拒绝 / 出款失败的不计入 / 退回额度（当天可继续用）。
④ 两道门取小：用户实际可提 = min（可提额度[打码流水]，VIP当日剩余额度）。VIP当日剩余 = max(0, VIP每日上限 − 今日已用)。
⑤ 时区：按 马尼拉 Asia/Manila (UTC+8) 自然日；每日 00:00 已用额度清零。
⑥ 升级引导：超额弹窗提供「提升 VIP」，文案统一为 「升级 VIP 可获得更高的单日提款额度」。
⚠️ 额度占用 / 释放（防拆单绕过，务必实现）
虽然最终按「成功」计，但提交/审核阶段必须先"预占"额度，否则用户并发拆单可绕过总额度。规则：
  • 提交时：校验「今日已用（成功）+ 处理中（预占）+ 本次金额 ≤ VIP每日上限」，通过才受理，并对本次金额预占。
  • 出款成功：预占转为正式「已用」。
  • 被拒绝 / 出款失败退回：释放预占（额度退回，当天可再用）。
最终效果 = 只有成功的占额度、失败的退回，且并发/拆单都无法超过每日上限。

4 场景与弹窗（图例）

场景 A · 未提过，单笔超每日上限（VIP0 上限 500，直接提 2000）→ "当前 VIP 每日提款上限 ₱500，本次已超限，请修改金额或提升 VIP。" ［修改金额］［提升 VIP］
场景 B · 累计超限（最常见）（今日已成功提 300，再提 400，累计 700 > 500）→ "今日剩余可提 ₱200，请修改金额或提升 VIP。" ［填入剩余额度→自动填 200］［提升 VIP］
场景 C · 今日额度用完（已成功提满 500）→ "今日提款额度已用完，请明日再试或升级 VIP 获得更高额度。" ［知道了］［提升 VIP］
场景 D · 流水没够（门1）（每日额度还有，但可提额度不足）→ "需完成投注要求才能提取，当前可提 ₱[可提额度]。"（勿写成"额度不足"）
场景 E · 单笔低于 100（提 50）→ "单笔最低提款金额为 ₱100。"
场景 F · 处理中占额度（有 400 处理中，再提 200，400+200 > 500）→ "今日剩余可提 ₱100（含处理中订单），请修改金额或提升 VIP。"
场景 G · 前单被拒/失败退回 → 该笔金额释放，今日剩余恢复，用户可正常再提（无弹窗）。
场景 H · 跨零点 → 马尼拉 00:00 已用额度清零，昨日用尽今日可正常提。
场景 I · VIP 升/降级 → 当日剩余实时按新上限重算；降级后若已用 > 新上限，剩余为 0、阻断（触发场景 C）。

5 与「免审 / 自动出款」的关系（别混淆）

本次的「每日提款额度上限」是限制闸门（超了不让提）；现有的「免审额度 / 每日免审次数」是出款审核方式（决定走自动出款还是人工审核），两者各管各的：

  • 额度上限：先判断这笔能不能提（两道门）。
  • 免审规则：能提之后，判断走自动出款还是人工审核（≤免审额度且未达每日免审次数→自动；否则人工）。

数值上「每日提款额度上限」沿用了「免审额度」的数字，但是两个独立配置，后续可分别调整。

6 配置项 & 前端展示

  • 配置：VIP0~9 每日提款额度上限（见第 1 节，后台可配）；单笔最低 100（全局，可配）。
  • H5 展示："Available to withdraw" 显示 min(可提额度, VIP当日剩余)；建议同时能看到「今日剩余额度」。
  • 去掉：每日次数限制相关的判断与文案。

7 测试要点（验收清单）

  • 单笔 < 100 拦截；= 100 通过。
  • 两道门取小：打码不足 / 每日额度不足，各自弹对的提示。
  • 累计：多笔成功累加到上限后拦截；「填入剩余额度」填的是 min 后的剩余。
  • 预占/释放：提交预占、成功转已用、拒绝/失败释放退回（当天可再提）。
  • 并发拆单：同时发多笔小额，总额不得超过每日上限（防绕过）。
  • 跨马尼拉 00:00 清零；VIP 升/降级当日剩余实时重算。
  • 次数限制已彻底移除（提任意多笔只受总额度约束）。
