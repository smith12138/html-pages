说明

本清单替代旧版《会员评定测试账号清单》。旧版是为「层级/标签/VIP 三套事件驱动评定」准备的，
2026-07 改版后层级已取消、评定改为定时全量重算，旧账号的用途（验证事件触发、手工拉入）已失效。
新模型下「测试账号」的含义变了：不再是"造一个号去触发评定"，而是"平台上真实满足某条件的会员"——
因为规则引擎每次全量扫描存量会员，所以验证的关键是「命中集是否与条件一致」。
本清单第一部分由标签引擎自身反查得出（对每个指标建一条规则标签 → 全量重算 → 读命中成员），
即系统认定满足该条件的真实会员，可直接用于核对"规则命中是否正确"。
覆盖全部 27 个指标，每个指标给出命中数（回归基线）+ 两个样本会员。
取样时间 2026-07-24，环境 staging，平台在册会员约 11933 人。

五、维护方式与已知数据缺口

一键刷新：第一部分可由脚本重跑——对 27 指标各建一条最小条件标签、启用重算、读成员即可，不需人工维护。
命中数骤变本身就是一条值得跟进的数据信号（可能是引擎变更或数据异常）。
已知数据缺口（影响命中集核对 TG-49，需产品/运营补数）：
1. 活动礼金 activity_gift_amount = 0、返水金额 rebate_amount = 1：奖励类指标几乎无真实数据，无法验证其命中正确性。
2. 总代/团队/小组各 1：代理层级维度样本严重不足。
3. 手机号已验证 = 是 为 0：全平台无已验证号，需实际走验证流程造样本（也可能是指标未落数据，见 TG-57）。
⚠ 注意：反查用的采样标签（smith_test_smp_*）为临时造数，读完命中集后已清空规则并删除，不应残留在标签列表。
若在后台看到 smith_test_* 标签，均为测试数据，可安全清理（python tools/tag_admin.py clear）。
