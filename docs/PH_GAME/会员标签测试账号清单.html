五、维护方式与已知数据缺口

一键刷新：第二部分可由脚本重跑——对 27 指标各建一条最小条件标签、启用重算、读成员即可，不需人工维护。 命中数骤变本身就是一条值得跟进的数据信号（可能是引擎变更或数据异常）。
已知数据缺口（影响命中集核对 TG-49，需产品/运营补数）：
1. 活动礼金 = 0、返水金额 = 1：奖励类指标几乎无真实数据，无法验证命中正确性。 2. 总代/团队/小组各 1：代理层级维度样本严重不足。 3. 手机号已验证 = 是 为 0：全平台无已验证号，需实际走验证流程造样本（也可能是指标未落数据，见 TG-57）。
注意：反查用的采样标签（smith_test_smp_*）为临时造数，读完命中集后已清空规则并删除，不应残留在标签列表。 若在后台看到 smith_test_* 标签，均为测试数据，可安全清理（python tools/tag_admin.py clear）。
