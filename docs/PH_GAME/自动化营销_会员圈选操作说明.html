自动化营销 · 会员圈选（人群组合）操作说明

营销旅程编辑器 → 人群组合面板 · 面向运营/产品 · 每个字段与组合逻辑一次看懂
一句话理解：人群组合就是「用几把筛子筛会员」。每把筛子（标签 / MASTER / TEAM / GROUP / CHANNEL / 名单）里，同一把里填多个 = 满足任意一个即可（OR / 取并集）；不同筛子之间 = 必须同时满足（AND / 取交集）。最终人群 = 通过所有已填筛子的会员。

一、核心规则（务必先记住）

规则含义
同级 OR同一个字段里填多个值（如两个标签 ID、两个 MASTER），会员命中其中任意一个就算通过这把筛子（取并集）。
跨级 AND① 代理/渠道内部：MASTER / TEAM / GROUP / CHANNEL 跨级之间固定为 AND（既在某 MASTER 下、又在某 CHANNEL 下…）。
② 不同来源类型之间（标签 / 代理渠道 / 名单）：默认也是 AND，但可由上方「人群组合」下拉切换成 OR 或 排除（见字段说明）。
只认「已授权」每个字段只能填你当前权限范围内已授权的 ID；填了没权限的会被拒绝。这是数据权限边界，不是圈人条件。
0 匹配也保留某个合法字段筛出来0 个会员时，系统照样保留这条限制（结果就是空/更小人群），不会自动放宽范围帮你凑人。填错=真的圈不到人。
留空 = 不筛某个字段不填=这把筛子不启用，不参与 AND。留空 ≠ 圈 0 人，而是「这一维不设限」。

四、字段逐个说明

字段是什么 / 填什么组合
全量授权会员
mode
 总开关，两态：已明确选择 / 未选择。开启「已明确选择」= 把你当前权限能看到的全部会员当作完整人群（对应 mode=UNRESTRICTED）。
必须显式打开才生效——防止误把「没设条件」当成「圈全量」。
⚠️ 一旦你填了 上传名单 / 组织(代理) / 标签 来源，全量开关会被自动关闭（不能又要全量又加筛子）。		 顶层开关
人群组合
relation · 3 选 1
 各来源之间怎么组合，三种模式：
• 同时满足所有来源（默认）= 各来源取 交集 AND，会员要同时通过所有来源
• 满足任一来源 = 各来源取 并集 OR，命中任一来源即可（用于扩大人群）
• 排除后续来源 = 从前面的人群里减去后续来源命中的会员（黑名单/排除法）		 OR / AND / 排除
标签定义 ID
selection_keys
 填会员标签的定义 ID（不是标签名），回车成为一个标签片(chip)；可填多个。圈出带这些标签的会员。
⚠️ 只有「已发布服务版本(serving version)」的标签才能用：光有标签评估还不够，标签必须有当前开放的服务快照；否则点估算会报 REFERENCE_REQUIRED: tag source needs definition, serving version, and snapshot ids。
注：标签按取数周期批量评估（非实时），以最近一次评估结果为准。		 同级 OR

五、实战示例（测试环境真实人数）

下面用测试环境两个真实标签演示 OR / AND / 排除 对人群的实际影响：
标签 1191「注册日期」= 15,847 人；标签 1192「首次充值日期」= 1,414 人（充值过的都注册过，所以 1192 是 1191 的子集）。

例 1 · 单标签：标签定义 ID = [1191]
→ 人群 = 15,847 人（带「注册日期」标签的全部会员）
例 2 · 同级 OR（同一字段填两个标签）：标签定义 ID = [1191, 1192]
→ 人群 = 15,847 人（1191 或 1192 = 并集；因 1192 全在 1191 里，并集仍是 15,847）
例 3 · 跨来源 AND（人群组合=同时满足所有）：把 1191 当一个来源、1192 当另一个来源做交集
→ 人群 = 1,414 人（1191 且 1192 = 交集，明显变小）
← 交集只有 1,414，条约填得越多、AND 后人群越小
例 4 · 排除后续来源（黑名单/减法）：人群组合 = 排除后续来源，前置 1191、后续 1192
→ 人群 = 14,433 人（15,847 减去 也带 1192 的 1,414 人 = 只注册没首充的）
一眼看懂 OR / AND / 排除：同样两个标签，OR=15,847（并集，最大）、AND=1,414（交集，最小）、排除=14,433（差集）。想扩大人群用 OR，想精准收窄用 AND，想去掉某批人用排除。
⚠️ 常见误区
  • 以为留空=圈0人：留空是「这一维不筛」，不是圈不到人。想圈全量请开「全量授权会员」。
  • 以为填多个字段会变多：跨字段是 AND（交集），填越多字段，人群越小不是越大。想扩大人群应在同一字段里多填（OR）。
  • 标签不实时：标签按取数周期评估，刚打标/刚改条件的会员可能要等下一轮评估才进人群。
  • 0 匹配不报错也不放宽：某字段筛出 0 人，最终人群就是 0（或被这一维压成 0），系统不会自动去掉这个条件。发人群前建议先看预览人数。
  • 只能填已授权 ID：填了权限外的 MASTER/TEAM/GROUP/CHANNEL/标签会被拒，不是 bug。

六、操作建议（发人群前自检）

  1. 先想清楚要「缩小」还是「扩大」：缩小→加字段（AND）；扩大→同字段多填（OR）或减字段。
  2. 要圈全量→开「全量授权会员 · 已明确选择」，别靠留空。
  3. 填完看预览人数：为 0 先排查是不是某个字段填了权限外/无匹配的 ID，或几个字段 AND 交集太窄。
  4. 用CSV 名单做定向时记得「上传并校验」，确认后名单即固定（快照），后续该名单变动不影响本次。
  5. 依赖标签的人群，确认目标会员已在最近一次标签评估里被打上标（新号/刚改条件的号可能还没进）。

七、根资格条件（人群之外的第二层过滤）

圈出人群后，还可以加一层「资格条件」按会员的行为/属性指标再过滤（如「注册满 N 分钟」「从未成功充值」）。这层和人群是 AND 关系：既在人群里、又满足资格条件的会员才最终进入旅程。

条件是一棵「布尔树」

  • AND / NOT / LEAF 组成：LEAF 是一个具体判断，AND/NOT 把多个 LEAF 组合。
  • 每个 LEAF（叶子条件）由 4 项组成：
    • 指标：判断什么（如 registered_elapsed_minutes 注册已过分钟、never_successfully_deposited 从未成功充值）
    • 比较：怎么比（GT 大于、EXISTS 存在 等）
    • 值：比较的目标值
    • 计算时点：什么时间点取指标（如 RUN_START 每轮运行开始时）
⚠️ 三值逻辑（重要）：条件判断是真 / 假 / 未就绪三种结果，「未就绪的事实不会被当成'未发生'」。即某会员的某项数据还没算好时，系统不会误判为「不满足」把他错误排除，而是等数据就绪再判。发人群时如果某些会员迟迟不进，可能是其指标数据还没就绪。

八、实时人群预估（发之前先算人数）

配好人群+条件后，先保存草稿，再点「估算」，系统会按证据算出真实人数，给出 6 个口径：

口径含义
原始匹配只按你的人群条件筛出来的原始人数
当前授权其中在你当前数据权限范围内的人数
安全排除因合规/黑名单/静默等被安全排除的人数
可执行人数最终真正能触达执行的人数（= 原始匹配 − 越权 − 安全排除）
可短信触达其中可通过短信触达的人数
可站内信触达其中可通过站内信触达的人数
「没有证据不会猜测人数」：不点估算就没有人数（显示"暂无数据"）；估算只在保存草稿后手动触发。提交审批前务必先估算、确认可执行人数不为 0 且符合预期。

九、预算上限

控制这条旅程的花费上限，四个口径：总预算 / 每日预算 / 单会员预算 / 单消息成本上限（均为 PHP）。

注：金额只提交 decimal 字符串，不在浏览器里计算或扣减预算（实际扣减由后端执行时处理）。

十、一条旅程从草稿到上线的顺序

顶部动作条：保存草稿 → 验证 → 估算 → 测试 → 提交审批 →（审批通过）→ 上线；旁边还有归档。

创建后是 DRAFT 草稿；人群、合规、审批必须在提交前完成。编辑区分四步：①人群与条件 ②运行设置 ③工作流动作 ④检查发布。运行上下文里能看到：版本状态、下次检查时间、参与者最长生命周期（如 90 天）、静默期（如 22:00–08:00 UTC+8）。
