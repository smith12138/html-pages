一、方案概述与关键改动

基于 PH01 项目 FAQ 知识库，针对菲律宾市场（Salesmartly 接入）的智能客服流程

本方案面向 PH01 项目（通过 Salesmartly 在线插件接入，project 770364 / channel 796065）的菲律宾市场智能客服场景，以官方 FAQ（17 条）为知识底座，重做接待与处置 SOP。与巴西 TT 包网方案的主要差异如下：

① 支付/货币/语言本地化

支付渠道为 GCash / Maya（Paymaya）（非 PIX/SPEI）；货币为 PHP（₱）；界面与话术为 English / Tagalog。注册采用 手机号 + OTP 验证。

② FAQ 知识库驱动

将 17 条官方 FAQ 结构化为「意图 → 标准答复 + 操作路径」，AI 直接命中知识库给出可执行步骤（如 Deposit / Withdrawal / Bind Wallet 的点击路径），减少臆测与转人工。

③ 需核实类问题分流转人工

充值/提现未到账、账号找回/删除/改号、账号受限/风控等需核实场景，收集 UID + 凭证截图后创建工单转人工，其余走 AI 自动闭环。

④ 用户信息查询尽量走后端接口

PH 项目自研，账户状态 / 订单 / 流水 / 奖励等查询类问题优先调后端接口拿实时状态，减少让用户截图与等待；AI 一律以 uid 为主键调用。所需接口见第四节（建议稿，待后端确认）。

分支总览： 账户（注册/用户名/密码/删号）充值（GCash/Maya） 提现（流水/到账）钱包绑定/解绑 投注历史优惠/彩金/返现

UID 自动携带：前端在 Salesmartly 插件初始化时携带 用户ID(UID)+平台，我方后台经 Webhook 解析绑定会话；AI 收集环节直接复用 UID，无需向用户索要账户ID；插件未携带时降级引导用户提供手机号 / User ID 核验。
⚠️ 高风险规则（须在话术与测试中重点覆盖）：官方 FAQ 明确「登录密码 = 提现密码（login Password is same to WITHDRAWAL PASSWORD）」。绑卡/解绑/提现均以该密码校验，属安全敏感点；AI 不得在会话中索取或回显密码，仅引导用户自行操作。

四、后端接口设计（自研 · 建议稿）

PH 项目为自研，用户信息与订单状态尽量走后端接口查询；以下为 AI 客服所需接口清单，待与后端确认字段与认证
设计原则：① 所有「查询类」问题优先调后端接口拿实时状态，减少让用户截图/等待；② UID 由插件携带，接口一律以 uid 为主键；③ 以只读查询为主，写操作（建工单）单列并需人工介入；④ 金额单位分（÷100=₱），时间 UTC/ISO8601 → 马尼拉时区（UTC+8, PHT）展示，订单号/手机号/钱包号等敏感字段脱敏。
认证（建议，待后端确认）：服务间调用建议 app_id + timestamp + sign 签名（HMAC-SHA256，服务端校验 ±5 分钟防重放）；或内网服务令牌。以后端实际方案为准。

说明：本节为建议稿，接口路径 / 字段 / 认证方式均需与后端对齐；PH01–PH10 若共用同一后端，建议 uid 之外带 platform_id/product_id 以区分产品线。
