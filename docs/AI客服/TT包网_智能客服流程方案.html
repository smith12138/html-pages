一、方案概述与关键改动

基于智能客服 SOP，针对 TT 包网（Salesmartly 接入）的三项核心改动

本方案在原「智能客服 SOP 流程」基础上，针对 TT 包网通过 Salesmartly 在线插件接入的场景重做，主要变化如下：

① UID 由插件携带，省去 AI 引导

前端在 Salesmartly 插件初始化时即携带 用户ID(UID) 与平台，我方后台通过 Webhook 解析获取。AI 无需再引导用户提供账户ID，收集环节直接复用 UID。

② 接入包网 4 个开放 API

包网提供 玩家信息 / 充值订单 / 提现订单 / 奖励记录 四个查询接口（MD5 签名鉴权，v2.0），AI 客服直接调用查询实时状态，替代/补充人工转发三方群。详见第五节。

③ 补充更细的问题分支

引入 tt-workflow 的细分分支：提现 10 态状态机、充值 5 态、游戏错误 spin/bet/reward、页面问题、设备兼容、奖励记录分析与「奖励缺失」分支。

分支总览： 充值（②API）提现（③API） CPF 绑定/修改账户（①API） 游戏/设备/页面活动奖励（④API）

五、包网开放 API 说明（v2.0）

external-api v2.0（2026-06-19）· Base URL https://{tenant-domain}/api/external/v1 · 认证：MD5 签名
v2.0 认证变更 ⚠️：由 v1.x 的 Authorization: Bearer <token>（JWT）改为 MD5 签名。每个请求都需附带 app_id + timestamp + sign。

鉴权（MD5 签名）

  • 凭证：appId（ak_ 前缀）+ secretKey（64 位 hex，仅创建时返回一次，请妥善保管）。
  • 签名步骤：① 收集除 sign 外所有参数 → ② 按 key 字典序升序（空值跳过）→ ③ 拼接 key1=value1&key2=value2 → ④ 末尾追加 &key=<secretKey> → ⑤ 取 MD5（32 位小写）即为 sign。
  • 防重放：必带 timestamp（Unix 秒），服务端校验 ±5 分钟，超时或缺失即拒绝。
  • POST 请求：Body 字段与 Query 参数合并后一起签名，sign 本身不参与签名。
示例（GET 玩家信息）：拼接串 app_id=ak_xxx&timestamp=1750348800&uid=149…&key=<secretKey> → sign=md5(上串) → 请求 /player/profile?uid=149…&app_id=ak_xxx&timestamp=1750348800&sign=<MD5>

下列接口的「请求」均为业务参数，另需附加 app_id + timestamp + sign（见上方签名说明）：

接口请求关键返回字段
① 玩家信息
账户分支		GET /player/profile?uid= uid · register_time · account_status(active/disabled) · level(VIP) · phone_masked
② 充值订单
充值分支		GET /recharge/orders?uid=&status=
分页 page/pageSize		 recharge_order_id · amount(分) · create_time · status · complete_time
③ 提现订单
提现分支		GET /withdraw/orders?uid=&status=
分页 page/pageSize		 withdraw_order_id · amount(分) · create_time · status · review_time · complete_time
④ 奖励记录
活动分支		GET /bonus/records?uid=&activity_name=&activity_key= activity_id · activity_name · activity_key · subcategory · reward_amount · claim_time

充值订单状态（status）： 0 待支付1 回调成功2 下单失败3 回调失败4 已过期

提现订单状态（status）： 0 出款中1 回调成功2 下单失败3 回调失败4 待下单5 待审核6 审核通过7 审核退还8 审核没收9 人工复审

通用约定：所有请求附加 app_id + timestamp + sign；金额单位为分（÷100 转元）；时间为 UTC / ISO 8601；订单号、手机号等敏感字段已脱敏；列表接口支持分页（pageSize 最大 100）。错误码：0 成功 / 7 业务失败 / 401 未认证（缺 app_id / app_id 无效 / 凭证过期）/ 403 签名验证失败或无权限 / 404 资源不存在 / 500 服务器错误。
