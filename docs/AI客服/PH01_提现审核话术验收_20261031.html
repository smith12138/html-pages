提现审核中：按 VIP 档解释免审规则

玩家问「提款怎么还没到账」，原先只回一句“审核中请等待”。本次改动补上三件事：这笔是哪一笔、他这一档的免审规则、以及该不该建议取消重提。下面是真实 LLM 路由下，玩家原话与 AI 实际回复的逐条记录。

结论

  • 7 种「提款没到账」的问法 —— 含他加禄语、Taglish、拼写错误 —— 全部正确路由到 check_withdraw_status；3 条容易抢路由的对照项也没有串。
  • 新分支两种情形的话术都正确：金额超过免审额度时建议取消重提，未超过时只解释规则。
  • 最关键的一条保护生效了：金额没超时，话术里连「取消」这个词都不出现。让玩家取消一笔正在正常审核的订单，等于白白作废、重新排队。
  • 响应时间 1.2–2.9 秒，与改动前持平 —— profile 与 rules 并发取，规则走 10 分钟缓存。

关键差异

两种场景的回复只有最后一句不同，而这一句正是本次改动的核心判断。玩家 VIP2，该档免审额度 ₱1,500.00、每日 2 次。

未超限
订单 ₱1,200.00 ≤ 免审额度 ₱1,500.00

It will be released as soon as the check is done.

只解释规则，不提取消。原因不在金额上，就不往金额上指。

超限
订单 ₱5,000.00 > 免审额度 ₱1,500.00

If you would rather not wait, you can cancel this request and submit a new one for ₱1,500.00 or less — that one would be released automatically.

金额确实超了，才给出可执行的下一步。

本轮没有覆盖到的

未覆盖横切护栏整条链路

本轮直接驱动 agent 验路由与 Skill 内部逻辑，绕过了 handle_turn_ph，因此情绪升级、重复回复、无推进、共情前置这四道护栏都没有走到。另一个需求（情绪安抚）已研判出的三个护栏问题，不在本轮测试范围内。

未覆盖免审额度为 0 的档

生产后台实测 VIP0 的免审额度就是 0.00，这一档任何金额都要人工审核。代码里对此有单独分支（不说“每次最高 ₱0”、不建议调金额），已有单元断言覆盖，但尚未用真实 LLM 端到端跑过。

数据限制超限场景靠改 mock 构造

内置 mock 的订单金额写死 ₱1,200，超限场景是临时把 mock 返回值抬到 ₱5,000 打出来的，业务代码一行未动。真实验收仍需测试环境里一个真有“审核中且金额超免审额度”的账号。

行为差异带时间词的问法走聚合路径

「I withdraw 3000 pesos yesterday」因为带了时间维度，走的是既有的 time_scope 聚合逻辑，答“昨天没有提现记录，最近一笔是…”。答得没错，但新的 VIP 规则说明不会出现。若运营希望这种问法也给规则说明，需要单独处理。

测试方式：真实 deepseek 路由调用 + 内置 mock 接口，串行限速；不读写任何真实玩家数据。
mock 账号 uid 末位 2 → 最近一笔 pending_review、VIP2；免审额度与每日次数全部实时取自 /withdraw/rules，代码中无任何写死数字。
