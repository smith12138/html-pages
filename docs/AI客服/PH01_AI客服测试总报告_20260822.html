五、关键机制发现(供研发/产品参考)

① 转人工=静音:任何触发转人工(玩家主动/诈骗安全/风控/注单争议/账户受限)的会话,AI 之后对该访客不再应答。转人工工单字段完整(平台/产品/账户ID/问题类型/说明),工作台可见。
② 身份绑定方式决定数据能否返回:账号在会话更早消息单独绑定后再问,AI 能正确返数(实测打码量 ₱28.50 与 CS API 一致);但同句"UID+问题"则触发 P1 丢弃 bug。真机玩家为登录态,但"报UID+说问题"合并习惯仍会踩坑。
③ 转人工分流正确:诈骗→【安全】、主动→【玩家主动】、注单争议→【三方查询·注单争议】、账户受限→先要求身份识别不泄露风控细节。分流与工单标注基本准确。
④ 币种/话术基线正确:金额均以 ₱(PHP)展示(₱15/₱28.50);删号"不可删"、注册"字母+数字密码"、忘密 Forgot 流程、15彩金"一人一号/同IP不合格"等话术准确。

六、结论

  • 基础话术与流程分流达标:FAQ 类(充值/提现流程、注册/找回/加密码、绑钱包、投注历史、优惠/彩金/返现/奖励历史)及转人工分流,绝大多数正确(37/62 通过)。
  • 核心待修 4 个 P1:①"UID+问题同句丢弃"(影响面最广、阻断关键流程);②"密码分享安全处理不一致";③"未验证UID即披露账号信息+充值明细"(隐私/PII);④"指导自称未成年注册"(合规红线)。
  • 待确认(验证受阻):打码量准确性——staging 的 admin quota 引擎对所有账号(含已成功提现者)返全0,不可作真源;Tacnode 不可达;CS API turnover 内部一致疑正确但缺旁证,需研发在正规环境复验(降级为 P3 待确认,非已证实缺陷)。
  • 7 个 P2:本地化(Tagalog)、多意图、解绑误转人工+情绪误判、登录=提现密码事实、密码校验话术、责任博彩/自残无危机干预、违规/AML询问未拦截。
  • 1 个 P3:多类概念/边界问题"答不到点"(给相邻FAQ而非直接答案),体验优化项。
